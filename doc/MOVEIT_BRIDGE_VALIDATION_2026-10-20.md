# MoveIt 真机桥接实现与验证

日期：2026-10-20（Asia/Shanghai）。本轮由代理执行模拟验证和真实只读验证，
没有执行真实机械臂轨迹、使能电机、切换示教模式、标零或更改固件。

## 已实现

新增 `piper_moveit_bridge` 包：

- 默认只读 CAN 网关；关闭 SDK 自动初始化请求，启动不发送 CAN 数据。
- 六轴真实反馈按精确角度单位换算；状态与反馈新鲜度检查。
- MoveIt 所需的机械臂/夹爪 FollowJointTrajectory action。
- 轨迹名称、时间、位置、速度和反馈校验，串行控制、取消、超时、到位判定。
- 电机使能、网关输出和桥接执行分别显式控制。电机使能服务不附带夹爪闭合或关节归零。
- 默认仅规划的小步工具；需要 `--execute` 和两个已开启门控才允许请求执行。
- 真实时间、同一 URDF 的 MoveIt/RViz 启动；没有 mock ros2_control 或 Gazebo 依赖。

同时修复原 MoveIt 虚拟模型 Xacro 引用 Gazebo 描述文件的问题，使原 demo 可独立启动。

## 实际运行结果

| 检查 | 结果 |
|---|---|
| 模型/轨迹纯逻辑测试 | 9 项通过 |
| 原 MoveIt -> GenericSystem 虚拟执行 | 规划成功、执行成功，joint1 目标 +0.03 rad，反馈误差 <0.003 rad |
| 新桥接独立 action 回归 | 成功、取消、并发拒绝、异常轨迹、夹爪换算、反馈超时、恢复不自动重启、实测到位判定均通过 |
| 假 SDK/CAN 网关回归 | 被动启动、只读拒绝、示教/限位拒绝、电机使能不夹爪闭合、陈旧/超速指令拒绝、超时门控均通过 |
| MoveIt -> ExecuteTrajectory -> 新桥接 -> 假硬件反馈 | 规划与执行成功，目标 +0.03 rad，实际反馈误差 <0.003 rad |
| 小步工具默认仅规划 | 规划成功，无执行请求 |
| 真实 CAN -> ROS 反馈 -> MoveIt 规划服务/模型 | 启动正常；8 秒检查收到 777 条反馈；CAN TX 增量为 0 |

模拟测试使用隔离 ROS 域且没有 CAN 网关；真实检查使用 read_only=true，未开启任何输出。

## 当前实物尚未通过运动前置条件

真实反馈仍显示 ctrl_mode=2、teach_status=1（示教记录中），joint2 约 -1.596°，
夹爪原始开口 -0.0002 m。示教状态和六轴越界均会拒绝启用输出。
这不是“桥接没写好”的替代检查；不能绕过后直接执行。

夹爪原始读数没有被覆盖。仅在 MoveIt 显示及反馈测量校验中允许边界外 0.5 mm 的
噪声带，并将单侧显示行程限制到有效范围；控制目标仍严格限制。六轴反馈不截断、不偏置。

## 环境层面剩余现象

本机 MoveIt 在退出时出现过 move_group 段错误；模拟执行过程及 ExecuteTrajectory
结果均为成功，新桥接进程可正常退出。还观察到 MoveIt action 客户端的
“unknown goal/result response, ignoring” 日志，但本轮对应执行结果成功。
这些依赖层现象已记录，没有通过屏蔽错误日志或升级系统依赖掩盖；
不把本轮结果表述为所有环境问题均已消除。

本流程未配置相机 Octomap，MoveIt 会提示没有 3D sensor plugin；
仍保留机器人自碰撞检查，不提供桌面、相机支架、线缆的完整自动碰撞保证。
